# Real-image data for the first Vero-to-brain-MRI recipe transfer

**Audit date:** 2026-10-15. **Purpose:** assemble genuinely visual, independently checkable brain MRI tasks for a direct Vero recipe transfer. This is a data and label audit, not a model-result claim. A task answer derived from one mask remains correlated with every other answer derived from that mask; do not call such questions independent clinical labels or independent transfer domains.

## Decision and immediate inventory

1. **Use the openly licensed Medical Segmentation Decathlon (MSD) Task04 Hippocampus now.** The official [MSD AWS registry](https://registry.opendata.aws/msd/) lists the public bucket and CC-BY-SA 4.0; the [MSD download page](https://medicaldecathlon.com/dataaws/) links Task04. The official tar, 28,425,216 bytes, was retrieved from `https://msd-for-monai.s3-us-west-2.amazonaws.com/Task04_Hippocampus.tar` into ignored `local_data/msd_task04/`; local SHA-256 is `282d808a3e84e5a52f090d9dd4c0b0057b94a6bd51ad41569aef5ff303287771`. Its embedded `dataset.json` declares MRI, 3D, labels background/anterior/posterior hippocampus, CC-BY-SA 4.0, 260 training images with 260 masks and 130 unlabeled challenge test images. **Local full-file validation:** all 260 training image/mask pairs decode as finite 3D NIfTI, have identical shape and affine within each pair, 1 mm isotropic spacing, valid labels {0,1,2}, and nonempty anterior and posterior masks. Image dimensions range only 31–43 × 40–59 × 24–47 voxels: these are small hippocampus-centered crops, so region-presence classification is especially shortcut-prone. This confirms image and mask bytes, not segmentation accuracy or subject independence.
2. **Use MSD Task01 BrainTumour as the second visual domain.** The same official [registry](https://registry.opendata.aws/msd/) exposes a 7,608,266,240-byte public tar, and its embedded `dataset.json` was read by exact HTTP byte range. It declares CC-BY-SA 4.0, 4D MRI channels `FLAIR`, `T1w`, `t1gd`, `T2w`; 484 labeled training and 266 unlabeled challenge test cases. Its *MSD-remapped* mask codes are background 0, edema 1, non-enhancing tumor 2, enhancing tumour 3; do not substitute original BraTS mask codes. **Local bounded-file validation:** eight four-channel training MRI volumes and their paired masks were extracted by exact HTTP byte ranges from the official TAR and SHA-256 recorded in an ignored private receipt. All eight image arrays are 240 × 240 × 155 × 4 with aligned 240 × 240 × 155 masks, RAS+ 1 mm isotropic geometry, finite values and expected labels {0,1,2,3}. This verifies **eight** actual paired cases, not the other 476. The [BraTS 2017 custodian](https://www.med.upenn.edu/sbia/brats2017/data.html) documents expert approved manual labels for its 2017 cases, but also explains that some earlier BraTS 2014–2016 annotations were algorithm-fused. The exact provenance of every MSD case must be mapped before calling all 484 independent human references. The complete 7.6 GB archive has **not** been downloaded. See the [eight-case visual prompt audit](MSD_TASK01_8CASE_AUDIT.md).
3. **Use Dallas `ds004856` for a distinct sequence recognition task and later longitudinal question.** The existing [Dallas audit](DALLAS_EXPANSION_AUDIT.md) records genuine CC0 T1/FLAIR MRI bytes with Git-annex integrity verification and BIDS sidecars. Sequence type is an independently recorded acquisition fact, though scanner/protocol cues can make it a shortcut task. Dallas longitudinal FreeSurfer measures are image-derived proxies and cannot serve as independent biological-change truth. Dallas subjects are not interchangeable with MSD tumors/hippocampi: dataset-source identification can masquerade as task transfer.

## Task taxonomy, ground truth and reward route

| Vero-like category | Immediate image and answer source | Exact verifier / reward route | Independence and shortcut boundary | Readiness |
| --- | --- | --- | --- | --- |
| Closed-set sequence recognition | Dallas raw T1 MPRAGE versus FLAIR with BIDS sidecar/acquisition metadata; Task01's four named channels may be rendered singly | Exact class answer; optional calibrated log score on held-out subjects | Sequence label is external to pixels, but pulse sequence and site style dominate. Mix source-balanced positives/negatives; no filename/metadata in prompt. | **Local genuine images and metadata verified**; class balance and subject-held-out split must be constructed. |
| Anatomical region presence / identity | Task04 3D MRI and two-region mask | Exact class or region-set match, using mask labels | Both answers derive from the same segmentation; Task04 hippocampus-centered crops leak the target location. Use full-view or out-of-crop external anatomy test before any generality claim. | **260 image/mask pairs verified**, weak as standalone reasoning task. |
| 2D box or 3D localization | Task04 anterior/posterior masks; Task01 tumor subregion masks | Hidden-mask 2D box IoU, center-distance and/or 3D box IoU; keep slice index and native voxel space explicit | 2D frame IoU is not 3D Dice. Bounding boxes are deterministic mask derivatives, not new expert labels. Make negative slices and size strata; enforce correct image/frame alignment. | **Task04 all 260 pairs verified**; Task01 eight image/mask pairs verified. |
| Numeric burden / counting | Task04 anterior/posterior component sizes; Task01 tumor subregion mask voxel count × voxel volume | Unit-checked tolerance or relative error, with exact frame/voxel spacing; component count only after predefined connectivity | Derived from same masks, correlated with localization. Counting connected components is algorithm-definition-dependent and may not equal lesion count. Compare image-only versus geometry-only and no-image controls. | **Task04 computable now**; Task01 eight pairs verified. |
| Segmentation-grounded spatial output | Task04 native 3D masks; Task01 pathology masks | Voxel Dice/surface-distance for full 3D output, or plane Dice for explicitly rendered slices | A standard Qwen3-VL renderer is 2D/multiframe and must not be mislabeled a native 3D segmenter. Dense mask generation may need a constrained coordinate/contour action format distinct from Vero's short-answer route. | **Task04 all 260 pairs verified**; Task01 eight pairs verified; model output interface still to implement. |
| Open-ended, grounded answer retention | Constrained natural-language question about visible mask regions in Task04/Task01, with answer criteria hidden from model | Prespecified semantic rubric plus mask-derived factual checks; human adjudication on held-out set | Free-form descriptions fabricated from a mask template are not independent radiology reports. No trustworthy local open-ended MRI report corpus is yet linked to these images. Retain an authentic open-ended arm only after source-permitted image/report linkage or expert authored questions. | **DATA BLOCKED for strong open-ended clinical claims**; limited grounded description possible as engineering test. |
| Longitudinal change | Dallas paired T1/FLAIR images | Predefined change target and QC/tolerance; clinical truth requires independent labels | This is one routed task, not a gate on all other categories. Existing FreeSurfer measures are pipeline-derived and protocol confounding remains. | **Real pairs verified; reward validity incomplete**. |

**Important unit of analysis:** Multiple prompts from one volume are one correlated cluster, and Task04 likely contains left/right hippocampal crops from the same original scan. The [MSD paper](https://pmc.ncbi.nlm.nih.gov/articles/PMC9287542/) reports 195 underlying people for the hippocampus source, whereas the downloaded tar has 390 volumes (260 training + 130 challenge test), and the challenge website describes 394 volumes (263 + 131). This discrepancy and absence of a patient crosswalk mean **patient-independent Task04 splits are unverified**. Do not treat 260 labels as 260 independent patients. Train/validation can be volume-held-out for an engineering pilot only; independent-patient inference needs source lineage or an external cohort.

## Minimum split and sampling contract for Vero transfer

- Define a *source patient* key before final train/validation/test partition. Retain all visits, sequences, crops, slices and derived questions from that patient in one split. For Task04, patient key is presently unavailable; any within-Task04 performance is a **volume-level engineering result only**. Cross-source external evaluation may be used where label definitions align.
- Make two nested matrices: **task category** (sequence, localization, numeric, open-ended, longitudinal) and **source cohort** (Dallas, MSD Hippocampus, MSD BrainTumour, later Mindboggle/ATLAS). Report both. A model can improve on categories while merely recognizing which source supplied the image.
- Predeclare renderer and Qwen3-VL visible evidence: native volumetric crops or slice grids, orientation, plane and frame order; hide filenames, acquisition fields, masks and target text. Use the same image representation, weights, token budget, number of verified rollouts and optimizer settings in single-category, proportional-mixture, uniform-mixture, SFT and MedGRPO controls. Record prefilter and postfilter effective category proportions.
- Reserve the official MSD challenge test images as unlabeled; do not claim test scores without reference masks. Hold out subjects from any synthetic question generation *before* generating prompts. Keep BrainTRACE sealed and never use its rubric to tune the reward router.
- Test no-image, shuffled-image, source-only and geometry-only baselines. Claim visual cross-task generalization only if gains persist against these shortcuts and on independent patients/sources with comparable label semantics. Derived questions from one mask do not multiply independent sample size.

## Local reproducibility and access notes

The official Task04 tar and eight Task01 image/mask pairs were downloaded into ignored `local_data/`. Reproduce Task04 with `curl -L --fail https://msd-for-monai.s3-us-west-2.amazonaws.com/Task04_Hippocampus.tar -o local_data/Task04_Hippocampus.tar`, then `tar -xf` locally. The local validation used `nibabel` and checked image/mask shape, affine, finiteness, mask values and nonempty class masks across all 260 labeled Task04 cases. The exact Task04 archive hash above identifies the inspected release; the publisher did not provide a checksum in the source page we found. The Task01 pairs were extracted with HTTP Range from offsets recorded in an ignored private index, then validated with `nibabel`; file SHA-256 values are in the private prompt manifest. No MRI image, mask, identifiable filename list, or individual measurement belongs in Git.
