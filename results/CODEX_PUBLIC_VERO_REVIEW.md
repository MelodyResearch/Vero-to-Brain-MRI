## Recipe reconstruction

- **Task sampling:** six domain weights are configured equally. The sampler floors per-batch quotas and assigns leftovers by largest remainder, then cycles through shuffled domain pools. At batch256/six equal domains this means four43-slot and two42-slot domains, not exactly equal proportions. Fixed rounding can entirely omit some positive-weight domains when batches are smaller than the number of domains. Missing configured domains are warned about and weights renormalized; available but unlisted domains are ignored. These are explicit source behaviors, not automatically defects. [Configuration](https://github.com/zlab-princeton/vero/blob/025ca3c800fc95224c86323c1f7fd33dceed3090/vero-rl/examples/model_runs/config/gspo_llmjudge_shared.yaml#L18-L28), [sampler](https://github.com/zlab-princeton/vero/blob/025ca3c800fc95224c86323c1f7fd33dceed3090/vero-rl/verl/utils/dataset/rl_dataset.py#L168-L246), [domain filtering](https://github.com/zlab-princeton/vero/blob/025ca3c800fc95224c86323c1f7fd33dceed3090/vero-rl/verl/utils/dataset/rl_dataset.py#L575-L619).
- **Rewards:** task route comes from `extra_info.reward_type`, while the adapter ignores `data_source`. The outer grammar requires one nonempty think block and one answer block. Boxed routes receive full format credit for one nonempty box, half format credit otherwise; the accuracy extractor can use the last box or recover a bracket-form box. A zero format score gates accuracy to zero, but half-format answers can retain full accuracy. At configured format weight0.2, a correct half-format answer scores0.9. This is the implemented contract, not an all-or-nothing single-box gate. [Parser and scoring](https://github.com/zlab-princeton/vero/blob/025ca3c800fc95224c86323c1f7fd33dceed3090/vero-rl/vero_reward/math_verify_reward_type_boxed.py#L1027-L1148).
- **Open-ended/judge tasks:** the config selects `vero_vllm_judge` and supplies a local judge endpoint, prompt and sampling parameters. The supplied ordinary reward helper deliberately returns zero for `llm_judge`; instruction-following checks return a fraction of satisfied constraints. The actual judge manager and its composition/error handling are absent. Therefore dummy-zero is **not evidence of a broken judge**, and actual open-ended retention/reward variance cannot be verified from these excerpts. [Judge config](https://github.com/zlab-princeton/vero/blob/025ca3c800fc95224c86323c1f7fd33dceed3090/vero-rl/examples/model_runs/config/gspo_llmjudge_shared.yaml#L95-L130), [helper](https://github.com/zlab-princeton/vero/blob/025ca3c800fc95224c86323c1f7fd33dceed3090/vero-rl/vero_reward/math_verify_reward_type_boxed.py#L779-L849).
- **Advantages/GSPO:** reward totals are grouped by prompt index, centered and divided by sample standard deviation plus epsilon; singleton groups use mean0/std1 instead. GSPO forms a masked response-mean log ratio, detaches that sequence quantity while preserving token-log-probability gradients, exponentiates after an upper clamp, applies asymmetric clipping and averages token losses within sequences. No obvious algebraic defect is established by this reading. Confirm masked gradients numerically before claiming implementation parity. [Advantages](https://github.com/zlab-princeton/vero/blob/025ca3c800fc95224c86323c1f7fd33dceed3090/vero-rl/verl/trainer/ppo/core_algos.py#L265-L328), [GSPO](https://github.com/zlab-princeton/vero/blob/025ca3c800fc95224c86323c1f7fd33dceed3090/vero-rl/verl/trainer/ppo/core_algos.py#L1036-L1099).
- **Likelihoods/optimizer:** the actor computes response-token likelihoods at the supplied temperature; minibatches reuse the optimizer injected into the actor constructor. Gradients accumulate across microbatches, followed by one optimizer step per minibatch. The one-minibatch/one-epoch branch replaces old log probabilities with detached current values, deliberately making ratios one for that on-policy branch. Float16 uses a gradient scaler; other precision checks finite gradient norm before stepping. Optimizer construction, scheduler, save/load and trainer lifecycle are outside the excerpt. ## Focused findings and decisive tests

### 1. P1 — `CONFIRMED_DEFECT`: flat-list image-size metadata is discarded

`_extract_image_size` takes the first item whenever the supplied value is a nonempty list; its later two-element list/tuple branch therefore cannot handle `{"image_size": [100,200]}`. That input returns `None`, whereas a tuple `(100,200)` is accepted. A list containing a size tuple or dictionary also works. This is an input-shape inconsistency visible directly in [lines386–404](https://github.com/zlab-princeton/vero/blob/025ca3c800fc95224c86323c1f7fd33dceed3090/vero-rl/vero_reward/math_verify_reward_type_boxed.py#L386-L404).

**Consequence:** grounding/clicking receives missing explicit size for a conventional JSON shape. **Rival explanation/limit:** upstream may always supply nested shapes or recover dimensions from `image_path`; actual score corruption is not established. **Minimal fix/test:** discriminate a numeric length-two flat sequence before unwrapping an outer list; test flat list, tuple, nested pair, dictionary, missing and malformed values, then equivalent normalized-coordinate scoring through the real handlers.

### 2. P1 — `CONFIRMED_DEFECT`: nonfinite numeric tolerance is accepted

Tolerance validation rejects negative values but not infinity or NaN. With `tolerance=inf`, finite gold1 and prediction999 satisfy the relative-tolerance branch and receive numeric credit. NaN is accepted but makes comparisons fail, silently changing reward behavior. [Tolerance extraction](https://github.com/zlab-princeton/vero/blob/025ca3c800fc95224c86323c1f7fd33dceed3090/vero-rl/vero_reward/math_verify_reward_type_boxed.py#L330-L342), [comparison](https://github.com/zlab-princeton/vero/blob/025ca3c800fc95224c86323c1f7fd33dceed3090/vero-rl/vero_reward/math_verify_reward_type_boxed.py#L902-L931).

**Consequence:** malformed metadata can disable numeric discrimination. **Rival explanation/limit:** no evidence that the actual dataset supplies such tolerance values; this is validation robustness, not a demonstrated training failure. **Minimal fix/test:** require finite nonnegative tolerance and finite numeric candidates; test ±infinity, NaN, zero tolerance, near-zero gold and ordinary relative tolerance. Explicitly reject invalid metadata rather than silently widening tolerance.

### 3. P1 — `PLAUSIBLE_CONCERN`: unknown reward routes fail open into generic verification

Missing/invalid reward types only print a warning, then dispatch to `_default_acc_reward`, whose first branch gives exact case-insensitive matches full credit. A valid outer-tag answer `A` with unknown route and gold`A` can therefore score1 despite absent routing. [Route fallback](https://github.com/zlab-princeton/vero/blob/025ca3c800fc95224c86323c1f7fd33dceed3090/vero-rl/vero_reward/math_verify_reward_type_boxed.py#L1064-L1113), [generic exact match](https://github.com/zlab-princeton/vero/blob/025ca3c800fc95224c86323c1f7fd33dceed3090/vero-rl/vero_reward/math_verify_reward_type_boxed.py#L632-L640).

**Rival explanation:** intentional compatibility fallback may be part of the upstream contract. **Minimal test/fix:** test missing, misspelled and unsupported routes at dataset admission; if explicit routing is required, reject them before training. Do not remove intentional fallback without checking upstream schema/corpus.

### 4. P1 — `PLAUSIBLE_CONCERN`: inherited response-penalty length differs from Qwen3-VL response cap

Shared config sets both data response length and reward `max_resp_len` to16384; Qwen3-VL overrides data response length to18432 but does not override reward `max_resp_len` in its supplied32-line file. [Shared length settings](https://github.com/zlab-princeton/vero/blob/025ca3c800fc95224c86323c1f7fd33dceed3090/vero-rl/examples/model_runs/config/gspo_llmjudge_shared.yaml#L124-L129), [Qwen override](https://github.com/zlab-princeton/vero/blob/025ca3c800fc95224c86323c1f7fd33dceed3090/vero-rl/examples/model_runs/config/gspo_qwen3vl.yaml#L9-L32).

**Rival explanation:** an earlier soft penalty may be deliberate, or the unprovided manager/trainer may replace the value. **Minimal test:** inspect resolved Hydra config and exercise the actual manager at14336,16384 and18432 response tokens, including EOS versus truncation. Do not infer penalty magnitude or assert incorrect actual training from YAML alone.

### 5. P1 when transferring to small batches — `PLAUSIBLE_CONCERN`: nominal positive domain weight can receive zero slots forever

Per-batch quotas are computed once. For six equal domains and batch2, only two domains receive slots; four are never sampled. Largest-remainder tie order does not rotate across batches. [Quota construction](https://github.com/zlab-princeton/vero/blob/025ca3c800fc95224c86323c1f7fd33dceed3090/vero-rl/verl/utils/dataset/rl_dataset.py#L180-L200).

**Rival explanation:** intended exact-per-batch design with official batch256 avoids starvation at the default six-domain configuration. **Minimal test/fix for a transfer:** assert every required domain's realized quota is positive, or explicitly implement rotating residual quotas and verify cumulative exposure. Count unique examples and replacement frequency, since cycling a small domain does not create independent evidence.

### 6. `NOT_VERIFIED`: restart fidelity, judge rewards, packing parity and scientific retention

The sampler advances its batch cursor before yielding all indices; state serialization and dataloader checkpoint behavior are absent. A mid-batch interruption therefore warrants a replay test, but the excerpt does not prove a resume defect. Likewise packed/unpacked token likelihood equivalence, rollout-versus-actor parity, nonfinite scaler behavior, judge failure handling, scheduler persistence and checkpointed Adam moments require missing implementations and executed tests. An optimizer reference reused inside `update_policy` is evidence of persistence within that object, not proof of full restart fidelity.
