# Versioned experiment contract and tiered preflight

**Policy: `mri-execution-tiers-v1`; CPU branch tests pass.** The unconditional final `NOT_VERIFIED` exception has been removed through a scoped execution policy, with legitimate acceptance and invalid-evidence rejection tests. This implementation status is not a new model result. The completed SFT28 adapter, outputs, hashes, historical failed arms and scientific conclusions remain intact.

The immutable `mri-prompt-reward-v1` record includes the pinned Qwen3-VL base revision `0c351dd01ed87e9c1b53cbc748cba10e6187ff3b`, declared processor/tokenizer revisions, SHA-256 values for model, processor, tokenizer and chat-template files, exact system instruction and hash, assistant prefix, thinking flag, prefill semantics, generation settings and token cap, strict answer grammar, reward parser version, reward profile, train/development manifest hashes, and a diagnostic training record's rendered prompt, prompt-token, image-token and image-byte hashes. The contract ID is the canonical hash of the full record. A future job must save and name that ID in its receipt. Hashing a declared revision does **not** independently prove the local weights came from that remote revision; model provenance remains a separate acquisition receipt.

The CPU preflight checks the pinned Qwen3-VL config family and exact local processor/tokenizer classes, artifact hashes, rendered system/question/image placeholder/assistant prefix, decoded real image files, source and patient lineage, train/development patient separation, target separation from model-visible messages, and positive/negative **strict** reward behavior for each record. It checks current AC power and basic memory conditions before a substantial run. It detects a `pmset` contradiction in which the header says AC while the battery detail says `discharging`. A missing or altered manifest, parser profile, artifact, or patient split fails closed. This check is not a substitute for inspecting expanded visual-token tensors or verifying that the rendered prompt and token-ID artifacts came from the same model call. The saved image-token IDs represent the tokenizer's `<|image_pad|>` placeholder, not image patches.

The raw `preflight()` report continues to mark dynamic gates unverified: static inspection cannot prove model behavior. Tier A uses the same static contract/data/reward checks without requiring AC power. A Tier A return only authorizes CPU work. Model launchers must name Tier B or C and validate that tier before MLX import/model loading.

`require_launch_preflight()` accepts explicit `execution_tier`, `phase`, finite `launch_budget`, exact `launch_configuration`, `expected_starting_adapter`, `expected_temperature`, and `expected_review_sha256`. Tier B first diagnostic has no previous dynamic receipt prerequisite. It allows at most one update, three groups, eight total rollouts and 512 tokens per rollout. The actual runner must enforce strict task variance and finite gradients before updating and inspect changed weights and reload before continuation. B continuation allows at most three updates under the same rollout/token caps and requires reviewed dynamic evidence. Tier C requires dynamic evidence, explicit substantial authorization, acceptance criteria and matched-budget checks. Missing tier authorization remains blocked by default.

A separate reviewer authors an approval file bound by `review_scope(...)` to policy, contract, source hashes (training interfaces, reward and resource code), generation settings, starting adapter, exact launch configuration/output, budget and optional dynamic receipt. The reviewer communicates its digest separately through the orchestration channel. The launcher checks the independently supplied expected digest and exact scope. Reviewer kinds are `isolated_codex` and `claude_code`, recorded truthfully, with `PASS` or explicitly limited `PASS_WITH_LIMITATIONS`; `FAIL` and `NOT_VERIFIED` do not authorize launch. This process assumes trusted orchestration. A local JSON name or digest chosen by the implementer cannot independently authenticate a reviewer, and this does not claim protection from malicious code running as the same OS user.

Continuation retains the original raw-evidence checks and strengthens them: strict rewards are recomputed from linked training labels; the selected active group must contain correct and incorrect answers with every output satisfying strict format; wrapper task values must equal recomputed accuracies. Source contract/system/model/train-manifest/temperature/token-cap bindings are checked. Actual before/after adapter hashes must differ, gradient must be positive finite, raw prompt/image hashes must agree, and the fresh checkpoint reload receipt must identify the changed adapter and the selected training image. The representative image in the static contract need not be the active group's image. Stale code/contracts, changed adapter bytes, altered raw rewards, fake source declarations, mismatched reloads and substituted review files fail.

Its artifact/data/patient/reward checks passed, while the recorded power sample was discharging. Future SFT controls expose the same explicit Tier C review/digest/configuration/budget arguments and load the reviewed starting adapter instead of silently initializing different weights. Multiarm parent preflight exposes those arguments too. The sequential child-review path now pauses durably when the next child approval is missing, emitting its exact one-row manifest, route, seed, output and current adapter for independent review. Supplying that scoped child contract and independently received approval digest permits one bounded subprocess, whose own gate repeats validation. Resume recomputes completed raw rewards, saved artifact hashes, update/reload evidence and the adapter chain; changed history or partial in-flight work requiring recovery is rejected. Every child remains within the parent finite Tier C budget. Missing review is a recoverable pause rather than an unconditional exception. This CPU-tested orchestration path has not yet executed a real multiarm comparison.

The child authorization CLI accepts a path map via `--child-authorizations` and requires each expected digest separately via `--child-review-digest INDEX=SHA256`; digests embedded in the map are ignored. The trusted caller must obtain each digest from the actual independent reviewer. A future adapter hash cannot be preapproved. Six CPU orchestration fixtures exercise missing-review pause, valid child execution, full finite completion, stale-starting-adapter rejection, tampered raw/weight rejection and preserved-prefix resume. These fixtures simulate subprocess outputs and are not model-training evidence.

Independent review caught and corrected an integration error: the child manifest now lives under `manifests/step_NN/train.verl.jsonl`, outside the child's initially empty output directory. A CPU integration test executes the actual smoke runner through its empty-output check and stops at model loading with inert MLX import stubs. Resume additionally requires the saved pre-update adapter hash to equal the reviewed starting adapter, finite old/current log-probability discrepancies at most `1e-5`, and matching raw prompt/image/token inventories and hashes.

The sequential multiarm orchestration is an engineering pilot: every child starts fresh Adam state. Parent and per-child aggregate receipts explicitly record `optimizer_reset_each_group: true` and `exact_optimizer_resume: false`. Its process-boundary continuation preserves adapter weights, not optimizer moments or RNG state, and must not be presented as native uninterrupted Vero/GSPO training. A matched comparison using this runner would need this reset behavior held constant across arms and clearly reported. No actual multiarm arm has been run through the new path.
