These are **not** patient-independent held-out scores, a Vero versus base comparison, or evidence of MRI transfer. The Task04 answer formats share one mask. The Dallas prompt set has two subjects and known source/protocol cues. A Task04 subregion boundary may be weakly visible in an image-only crop, so even an eventual high reward would require center/no-image/occlusion controls. The immediate purpose is to verify real image-conditional model execution and diagnose a pretraining baseline before direct matched-checkpoint comparison. The same eight image/question pairs are queued for Vero as soon as its pinned local download is complete. A second source, MSD Task01 tumor MRI and masks, now has eight verified volumes and its own fixed-midpoint prompt set; base results follow below.

Six extra local controls were run on the base checkpoint: one no-image and one constant-gray image input for each of the three categories. For the selected anterior Task04 dominance question, the model said `anterior` for the real, no-image, and blank inputs. For the selected Dallas T1 question, it said `FLAIR` for all three. This demonstrates that the corresponding correct/wrong answers in this tiny pilot are not reliable evidence of visual use. On the centroid control the no-image response was an out-of-range coordinate and the blank-image response was invalid; neither matched the hidden target. These controls retain exact prompts and images in ignored private files, with no patient-level claim.

For the full 260 Task04 centroid targets, an image-free geometric-center predictor lands within the ≤3-voxel tolerance on **23/260 (8.8%)**; its mean distance is **5.659 voxels** and median **5.556**. This is a necessary coordinate shortcut baseline, not a trained result. It does not establish the target is visually recoverable from a rendered slice.

## Second source: real four-sequence tumor MRI

Eight verified MSD Task01 MRI/mask pairs yielded eight prespecified fixed-midpoint four-panel images at `z=77`. The first diagnostic used two hidden-mask questions per volume, 16 image-linked outputs total. The runner asserted exactly one Qwen3-VL image placeholder per prompt. The base checkpoint scored **7/8** on enhancing-tumor presence (sample majority-yes baseline **6/8**) and **2/8** on the tumor-centroid 3 × 3 grid cell (sample majority-cell baseline **4/8**); all 16 outputs parsed validly. Raw outputs and gold remain in ignored `local_data/frozen_eval_v1/`. These are source-volume-level exploratory outcomes, with only eight cases and no verified patient crosswalk. They do not justify a clinical sensitivity or transfer estimate. The separate all-positive any-tumor question was deliberately excluded because its always-yes baseline is 8/8. The label-balanced `z=40` slice was chosen after mask inspection and was not used in this first comparison.

The base output is an actual generated model response, not an imputed score. No neural weights were updated. The runner now asserts one Qwen3-VL visual placeholder for each image and supports no-image controls; the original eight-question base batch predates the explicit placeholder assertion, while the subsequent 24-question paired run passed it. The pinned released-Vero 8B checkpoint also generated on the same real MRI images. In its native chat template it produced long reasoning and did not reach a final answer in a 256-token one-image probe. The complete 24-question comparison therefore used the base model's template for **both** checkpoints and the same 256-token cap. Independent recomputation found base 12/24 correct, Vero 9/24, with Vero only 17/24 parseable. This measures frozen checkpoints and answer-format behavior on a tiny diagnostic, not the Vero multi-task training recipe. Full category results, provenance checks, baselines and limitations are in the paired audit.
