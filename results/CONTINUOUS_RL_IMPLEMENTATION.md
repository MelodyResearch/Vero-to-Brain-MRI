# Continuous local RL state: implementation and test evidence

## Mission alignment and scope

This change addresses R06: local multiarm child processes retained adapter weights but recreated Adam on each prompt group. It enables the required controlled Vero-to-MRI RL comparison to proceed once native and launch gates pass. It changes neither the historical results nor the MRI reward, task taxonomy, optimizer hyperparameters or GSPO loss. Evidence tier: **IMPLEMENTED / TESTED_CPU**; native integration validation and MRI RL remain separately gated. `CROSS_MODEL_REVIEW=NOT_VERIFIED` for these private project interfaces.

## Code actually implemented

- `src/mri_rl/continuous_rl.py`: backend-injected driver with one optimizer per live run, immutable whole-group boundaries, exact schedule/image/source bindings, persistent optimizer step/moments/RNG, atomic adapter+optimizer+cursor publication, exclusive writer lock, hash-chain verification before backend construction, skip checks and bounded continuation.
- `src/mri_rl/mlx_continuous_gspo.py`: lazy native implementation of the historical image/prompt rollout, old/current response likelihood, GSPO-token gradient and Adam update. It implements the backend interface used by the driver. It loads the current adapter exactly, restores Adam and both MLX/Python RNG after setup, and validates resumed tensors. The optimizer is created once in the backend constructor, not inside the group update.
- Historical `mlx_gspo_smoke.py` and `mlx_multiarm_train.py` are unchanged. Their reset profile remains reproducible and clearly distinct.

The driver uses strict task-routed reward parsing. A group updates only when every response has full format credit, task accuracy varies and the overlong penalties match. An inactive group advances the attempted-group cursor and sampling RNG but changes no weights, moments or optimizer step. There is no fallback to format-only rewards, relaxed parsing, dev-selected rollouts or synthetic MRI training data.

Atomic boundaries contain complete adapter, optimizer state, RNG, raw rollout and receipt evidence. A failed update/save leaves its `.pending-*` directory and prior committed boundary intact. Restart uses the last complete boundary; completed schedule work is not repeated. A hash-corrupt or changed-schedule resume is rejected before constructing a backend.

## Actual tiny native execution and its limits

`tests/test_continuous_rl_native.py` is opt-in and does not import MLX during default collection. It uses a 3×3 CPU model through the actual native GSPO update and likelihood indexing, real MLX Adam, safetensors and both RNGs. It compares continuous versus restored active→inactive→active execution and actual skipped weights. It loads no Qwen checkpoint or MRI image. The parent reserved a native idle window. The normal pytest command exited because this environment lacks pytest, so the exact test function was invoked directly with only its module-level pytest marker stubbed. Initial sandbox execution exited at MLX import (device unavailable); the authorized native retry then exposed a real `_RandomState` serialization failure. Copying its arrays into a list, matching the established SFT snapshot pattern, corrected that mismatch. The exact test then **passed and exited 0** on MLX 0.32.4. No Qwen/MRI model was loaded. The first successful native run preceded the additional publication/resource checks below. A second explicitly reserved idle window replayed the final hardened sources successfully: exit 0, MLX 0.32.4, `Device(cpu, 0)`, 0.167 seconds for the fixture. That replay actively blocked MLX-VLM, Torch and Transformers imports. Exact source hashes, receipt and actual synthetic checkpoints are retained privately in `local_data/ds007045_bounded/continuous_rl_native_final_v1/`. It verifies the real inherited GSPO update, state restoration and serialization, while the tiny fixture bypasses the Qwen constructor and real image generation.

## Independent-review corrections

Five additional regression cases were executed failing first, then passed after minimal corrections: frozen image changes inside authorization; NaN updated parameters; NaN Adam first moments; negative second moments; and a failed post-generation resource gate. The driver now rehashes the selected image after authorization and generation, checks the raw rollout image digest, and requires backend validation of finite trainable tensors/optimizer tensors and nonnegative second moments before publication. Every payload included in the committed inventory is fsynced. The complete raw group is saved before the post-generation resource gate, including for inactive groups. Native generation also saves incremental completed responses to the pending directory.

The native constructor now follows the established paced SFT loading discipline: memory/cache caps, lazy base loading, quantization before materialization, release of lazy float sources and language-layer gradient checkpointing. This is implemented source behavior, not fresh proof that a real MRI model fits memory or that the new launcher has been approved.

Four further lightweight tests call the actual native backend finite-state validator with NumPy array operations, checking its finite baseline, NaN parameters, NaN first moments and negative second moments. They import no MLX and do not substitute for native execution.
