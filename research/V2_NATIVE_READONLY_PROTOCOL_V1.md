## 2. Experiment A: Common32 teacher-forced rescoring

Inputs: the 32 real saved Common TRAIN responses from V2 segment 0.
- 2 SEQ units of F4+T4 and 2 Dallas units.
- All generated by Parent Adam52.

Each response is teacher-forced under A53, then under B53. The rules:
- Same F32 scorer (`SharedRolloutBackend._context_logps`).
- Same recorded prompt, image fingerprints, rendered prompt ids and frozen prompt length.
- The saved token ids are used as-is; responses are never retokenized.

Budget: exactly 32+32 = 64 forwards, each charged exactly P+len−1 TF positions.
- At preparation, P must equal both the recorded rollout length and the frozen V2 ledger (concise sequence length, Dallas 405).
- The exact per-checkpoint total is derived from all 32 jobs and frozen in the scope.
- The earlier 23,282 figure remains `NOT_VERIFIED` until root runs the CPU prepare.

Reference: the saved 52 own-old scores, which are the GSPO denominators.
- New scores are expected to differ.
- The training parity gates (old = current, 1e-5 / .002) are not applied.

Reported per response, privately:
- full mean / sum / first-token Δlogp;
- EOS Δ;
- mean Δ excluding EOS;
- two separately named answer-span families (below): label-only Δ (`delta_label_*`) and whole-overlapping-token Δ (`delta_overlap_*`);
- raw sequence ratio (log-ratio capped at 10, as in the native loss).

The historical strict parser, the reward and the native TF scoring are unchanged. All 32 full-response logp vectors are kept. The parser is only called, to decide which tokens a measurement may use.

Answer-token measurement eligibility (`answer_span`, computed on the saved token ids, never retokenized):
- Decode check. The saved ids are decoded, dropping a final special EOS token. The result must equal the saved text up to outer whitespace and must give the same historical parse (`_answer_and_format`). Otherwise the status is `DECODE_MISMATCH` and no positions are used.
- Region. The span is taken only from the region the parser grades: the box inside `<answer>`. Boxes in `<think>` are ignored, as the parser ignores them. A reasoning box therefore does not invalidate a single valid answer box.
- Status:
  - `STRICT_CANONICAL`: strict format, one answer box, canonical label;
  - `STRICT_NONCANONICAL`: strict format, one answer box, non-label content;
  - `MULTIPLE_ANSWER_BOXES`: more than one balanced box inside `<answer>` (parser format .5);
  - `EMPTY_ANSWER_BOX`, `MALFORMED_BOX` (unclosed), `NO_ANSWER_BOX`;
  - `FORMAT_INVALID`: the tag/think gate fails (parser format 0);
  - `DECODE_MISMATCH`.
- `label_metric_eligible` (`measurement_kind = LABEL_ONLY`) holds only when all three are true:
  - the status is `STRICT_CANONICAL`;
  - the answer contains no other `\boxed` markup (otherwise `EXTRA_BOX_MARKUP_IN_ANSWER`; the parser can still grade such a response as strict-valid);
  - the selected tokens start and end exactly on the label bytes (otherwise `PARTIAL_BPE_BOUNDARY`, e.g. `{FL`, `AIR}` or `1}`).
- Token probabilities are never split by bytes. A token that shares bytes with a brace, a `\text{` wrapper, a tag or a space makes the span ineligible; it is never trimmed.
- Every other span that has overlapping tokens is `WHOLE_OVERLAPPING_TOKEN_DIAGNOSTIC`: whole tokens overlapping the selected content. For `FORMAT_INVALID` this is the last balanced box anywhere; for `MULTIPLE_ANSWER_BOXES` it is the last answer box. These are content-overlap diagnostics. They are not visual accuracy and not label probabilities. Spans with no content tokens are `NONE`.
- Label-only metrics are `None` for ineligible spans, so they are never pooled with ambiguous, invalid or boundary responses. Overlap metrics are never pooled in any stratum. They are reported only per status, and only for ineligible spans (`answer_measurement.*.whole_overlapping_token_diagnostic_by_status`).
- Counts reported: eligibility per status, reason, task and measurement kind; exact-decode count; parser-format vs recorded-grade disagreements. The CPU prepare summary also carries these counts before any native run.
- Expected sizes: 'FLAIR' is about 2 tokens and 'contrast-enhanced T1' about 5. The real eligible counts are `NOT_VERIFIED` until root runs the CPU prepare.
- Full-response logp is not a canonical class margin.

The 2×2 surrogate (checkpoint × fixed A/B segment-0 plan):
- Formula: Σ .25·w·max(−A r, −A clip(r, 1−.0003, 1+.0004)), plus an unclipped variant and the count of ratios outside the clip range.
- The plans are re-derived and must match the saved `gradient_evidence`.
- It is descriptive. It is not a counterfactual training result.

Single-factor strata (full-response measures plus the gated label-only family):
- task;
- image;
- recorded format class (`STRICT_VALID` 1, `PARTIAL_FORMAT` .5, `FORMAT_INVALID` 0);
- raw (`CORRECT` / `RAW_ZERO`);
- raw outcome;
- advantage sign under plan A and plan B;
- answer status;
- measurement kind.

Raw outcome separates the reasons for raw = 0. A raw 0 is never called a wrong MRI class just because it is 0:
- `CORRECT`;
- `RAW0_FORMAT_GATE`: format 0, so the parser's answer is empty;
- `RAW0_CANONICAL_WRONG_CLASS`: the parser's answer is a canonical label of the other class;
- `RAW0_NONCANONICAL_OR_MISSING_ANSWER`.

Joint strata (`joint_strata`), task × recorded format class × raw outcome, per checkpoint (e.g. `MRI|STRICT_VALID|RAW0_CANONICAL_WRONG_CLASS`):
- So that MRI correct, wrong and invalid changes are not read off pooled Dallas+MRI statistics.
- Each cell carries n, label-eligible count, measurement-kind counts, the full-response measures and the label-only family.
- Each cell also carries the same checkpoint's fixed-plan A/B terms: admitted count, advantage sign counts, and the surrogate Δ contributed by that cell.
- The cells partition the 32 responses. Per plan, the cell surrogate Δs sum to the 2×2 cell Δ.
- Cells are descriptive. An n = 1 cell is a single response.

## 4. Execution safety (reused, unchanged)

Each checkpoint runs in one fresh child process, A53 first, then B53. At most 2 model loads; 0 recoveries.

Authority:
- Before any MLX import, the child needs:
  - the exact current CPU preparation, matching the scope;
  - an isolated non-Claude review of the scope, source and input hashes;
  - a fresh human permission (issued ≤30 min before launch, ≤24 h validity, naming A53 and B53, consumed once), which root records only after the researcher replies.
- Every bound source, input and checkpoint payload is re-hashed at the key phases.

Checkpoint load:
- The checkpoint is restored under its original manifest run binding.
- `verify_loaded_terminal` must pass (1942 / 1010 / 504, policy / Adam / RNG / step = segment-0 receipt).

Read-only phase:
- `_readonly` checks that all parameters and Adam are unchanged, then restores the loaded state, including RNG, in RAM.
- The full identity afterwards must equal the loaded identity.
- The on-disk checkpoint is re-hashed and never saved.
- No backward pass, optimizer call, TRAIN generation or checkpoint save is reachable (tested statically and with fakes).

Journal and release:
- Each TF score and each greedy row is one `safe_micro_journal_v1` operation.
- A claimed but uncommitted operation is `INDETERMINATE_NO_REPLAY`.
- Checkpoint output directories are one-time; there is no resume.
- Completion is committed only after `release_before_commit` (model is None, active memory <128 MiB) and a `run_with_release` verification.
- B53 starts only after the A53 child has:
  - exited 0;
  - been reaped;
  - released the global lock;
  - reached a PASS terminal;
  - passed release verification.
- Any other outcome stops everything. There is no retry, no B53, and no restart after RED.

Resources:
- `safe_micro_dynamic_resources_v1.POLICY` is unchanged.
  - GREEN / YELLOW continue.
  - RED releases the child's own model.
  - STOP triggers: RSS >14 GiB, MLX >12 GiB, available <2 GiB, <4 GiB for 30 s, pressure-free ≤15%, disk <26 GiB, battery <20%, and coupled swap deterioration.
  - There is no fixed 9/10 GiB floor, no swap-only cap and no 120 s hold.
  - The current battery-allowed policy is kept.
- The guardian is the existing `safe_micro_watchdog_v2`, acting only on its own child.
- The constructor uses the 12 GiB / 256 MiB cap.
- The final cache must match the pinned SHARDS, with 0 quantization and 0 recovery.
- Known limit: the monitor has a sampling blind spot during the model constructor.

Windows:
- Hard limits: 1200 s per checkpoint and 2400 s in total. Both are operation-start windows, both include non-resident waits, and neither is ever reset.
- Timing model: 90 + 32·5 + 4·(256·.25+3) = 518 s per checkpoint (`PLANNING_ESTIMATE_SECONDS_PER_CHECKPOINT`).
  - It is a planning estimate from the historical V1/V2 rates.
  - It is not calibrated for this run.
  - It is not a worst-case bound or a wall-time guarantee.
- Windows gate the start of each operation. An in-flight F32 forward or greedy generation is atomic and cannot be interrupted safely; only the guardian's signals can stop the child. Actual wall time can therefore exceed a window by the duration of one in-flight operation plus release.

## 5. Causality limits

- **A. Task interference.** No per-task gradients were retained. A read-only measurement cannot show an MRI–Dallas gradient conflict.
- **B. Fixed responses.** The TRAIN responses are fixed Parent samples. Post-update logp changes on them are not on-policy behaviour. The 2×2 is descriptive.
- **C. DEV sample.** The 4 DEV images were chosen because of the observed regressions, from a previously explored DEV set. Any result is diagnostic and carries selection bias.
- **D. Scale.** One seed and two checkpoints. There are no canonical class margins. Q1–Q4 outcomes localize the change; they do not prove its mechanism.

No new training fix is chosen until these native outcomes exist and are independently reviewed. The `PROPOSED` Adam-moment ablation in the root-cause report stays `PROPOSED`.
