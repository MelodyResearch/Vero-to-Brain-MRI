## 5. What would falsify the Paired-Prompt benefit; confounds; evidence sufficiency

- **Falsifiers (this configuration):** under the identical frozen prompt, B ≤ A in DEV24 balanced accuracy; or B’s T1 gain arrives through constant-answer shifts (CLASS_PRIOR_SHIFT_PLAUSIBLE) or matched FLAIR loss; or, on the identical 32 segment-0 responses, Paired-Prompt grouping does not admit more effective groups than same-prompt grouping (mechanism claim fails — an exact paired readout recorded as `mechanism_segment0_same_32_responses`).
- **Format confound:** the prompt condition is identical for Parent/A/B; invalid rate is reported, plus B-vs-Parent accuracy on cases valid for both. Prompt effect is computed as Parent(frozen prompt) − saved V1 Parent(original); RL effects only compare checkpoints under the same prompt.
- **Class-prior confound:** predicted-class counts plus pair transitions; a B gain without pair discrimination gains is not an image claim.
- **Sufficiency:** 24 images in 4 previously explored patients, one seed, ≤2 updates. A 2-case difference has a descriptive sign-test p ≥ 0.25. This pilot can falsify gross harm, measure the group-admission mechanism and decide whether a round 2 is worth proposing; it cannot establish a stable population effect. Frozen scale rule (`core.SCALE_RULE`): GO_PROPOSE_ROUND2 only if B beats A and Parent by ≥2 cases each, T1 recall rises, FLAIR does not drop by more than 1/12, invalid not worse (or valid-only gain), and the B-vs-Parent pair reading is IMAGE_CONDITIONED. **Method-specific criterion (frozen 2026-10-21, before any V2 output):** GO additionally requires that, B versus A over all 12 DEV pairs (invalid-involved pairs stay in the denominator), correct-discriminating pair gains minus losses is ≥ 2 and the reading is IMAGE_CONDITIONED_DISCRIMINATION_GAIN (`core.B_VS_A_MIN_NET_PAIR_GAIN = 2`). If B beats Parent but not A on this criterion, the decision is INCONCLUSIVE. Identical B/A pair category profiles are reported as `NOT_DEMONSTRATED_IDENTICAL_PAIR_PROFILES`. The analysis always sets `paired_prompt_image_grounding_demonstrated = False`, so it never claims Paired-Prompt-specific image grounding. With 12 pairs and a net gain of 2, this rule is deliberately conservative and still descriptive only. Round 2 (≤8 patients/≤4 updates) is never automatic.

1. *Journal counters:* segment 0's committed manifest included the mutable `arm_counters_PRIVATE.json`. Segment 1 then charged and overwrote that file, which invalidated segment 0's commit hash. Each journal operation (C, segment0, segment1) now commits an immutable `counters_after_PRIVATE.json` snapshot inside its own operation directory. The spent ledger is kept, and `resume_counters` refuses to restore it below any committed snapshot, so spent work is never refunded. A real-`Journal` two-segment CPU regression reproduces the old failure (`Committed artifact missing/changed`) and shows that the fix survives.
2. *Completed-stage revalidation:* `execute_chain` used to skip stages whose verified or skipped marker merely existed, and `_prior` only checked the immediate predecessor. Now `_completed` revalidates every completed stage on each resume and child admission, and again before analysis. For verified stages it checks the exact scope, terminal hash/PASS/release, closed exit, released lock and closed-log hashes. For skipped stages it re-derives the reason from committed predecessor terminals and requires no native artifacts. A stage marked both verified and skipped is rejected. Real-file CPU fixtures cover an early P-terminal change, a rewritten log, a forged EP skip and wrong skip reasons.
3. *`core.run_arm`:* if `segment_1` already exists, it now rejects at once, before any `load_checkpoint` call or backend mutation. The test asserts zero loader calls and an unchanged backend state.
4. *Level metadata:* see §3 (bound-source z045 provenance; no `levels=["None"]`).
5. *Scale rule:* B-vs-A paired criterion (§5).
